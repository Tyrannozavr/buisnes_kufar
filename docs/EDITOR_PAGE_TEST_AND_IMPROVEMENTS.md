## 1. Почему кнопка «Отправить контрагенту и сохранить» неактивна

**Причина:** Кнопка намеренно отключена, пока не выполнены условия:
- Открыта вкладка **«Заказ»** (на других вкладках кнопка не применяется).
- Нажата кнопка **«Редактировать»** (включён режим редактирования).

**Сделано:** Добавлена подсказка (tooltip) при наведении на кнопку:
- Если открыта не вкладка «Заказ»: *«Доступно только на вкладке «Заказ». Переключитесь на заказ и нажмите «Редактировать».»*
- Если не нажато «Редактировать»: *«Нажмите «Редактировать», внесите изменения в заказ, затем нажмите эту кнопку — данные сохранятся и контрагент получит уведомление.»*
- Если кнопка активна: *«Сохранить изменения и отправить уведомление контрагенту в чат.»*

Кнопка обёрнута в `span`, чтобы подсказка работала и при наведении на неактивную кнопку.

## 2. Генерация номеров (по ТЗ)

**По ТЗ:** Номер заказа — маска 00000, по возрастанию, ежегодное обнуление. Отдельная нумерация у покупателя и продавца.

**Реализация:** В бэкенде (`backend/app/api/purchases/repositories/`) реализовано:
- `_generate_order_number` — номер заказа (маска 00001, ежегодное обнуление, раздельно buyer/seller).
- `_generate_bill_number` — номер счета.
- `_generate_supply_contract_number` — номер договора поставки.
- `_generate_contract_number` — номер договора (услуг).

На странице редактора отображается номер заказа (например, 00002) — генерация используется при создании заказа и при отображении данных сделки.

**Итог:** Генерация номеров по ТЗ реализована на бэкенде и отображается в редакторе.

## 4. Рекомендуемые улучшения (по приоритету)

### 4.1. Обязательно

1. **Подсказка для кнопки «Отправить контрагенту и сохранить»**  
   Сделано: при наведении показывается текст в зависимости от состояния (только заказ, нужен режим редактирования и т.д.).

2. **Подключить компоненты к вкладкам редактора** (`frontend/pages/profile/editor/index.vue`):
   - Вкладка 3 «Сопроводительные документы» — монтировать `AccompanyingDocuments.vue`.
   - Вкладка 4 «Счет-фактура» — монтировать `Invoice.vue`.
   - Вкладка 5 «Договор» — монтировать `DogovorUslug.vue` (договор услуг/работ).
   - Вкладка 6 «Акт» — монтировать `Act.vue` (сейчас там ошибочно DogovorUslug).
   - Вкладка 7 «Другие документы» — добавить компонент или явную заглушку «В разработке» по аналогии с ТЗ.

3. **Фото/сканы документа**  
   Кнопка «Выберите файл» вызывает `inDevelopment()` (тост «в разработке»). По ТЗ: загрузка фото/сканов, отправка контрагенту, блок «Фото/сканы документа». Бэкенд (S3, API документов) упоминается как готовый — нужно довести UI и сценарий до рабочего.

### 4.2. Желательно по ТЗ

4. **Доработка бланков документов**  
   В компонентах есть комментарии «Сергей: доработать бланк по ТЗ» (Счет-фактура, Договор, Акт, Сопроводительные документы). Нужно привести поля и вид бланков в соответствие с ТЗ (реквизиты, таблицы, подписи, нумерация и т.д.).

5. **Кнопка «Заполнить данными»**  
   По ТЗ при нажатии — подтверждение «Данные будут изменены. Продолжить?». Сейчас подтверждение может быть не везде — проверить и добавить там, где нужно.

6. **Предварительный просмотр**  
   По ТЗ: кнопка в стиле MS Word, показ документа «как на печати». Проверить наличие и удобство такой кнопки во всех типах документов.

7. **Единицы измерения и ОКЕИ**  
   По ТЗ: каждой единице измерения — код ОКЕИ. Проверить, что в формах (заказ, счёт и т.д.) подставляется код по выбранной единице.

### 4.3. Дополнительно

8. **Подсказки для других неактивных кнопок**  
   «Заполнить данными», «Печать», «DOC», «PDF», «Редактировать», «Выберите файл» при `activeButtons === false` — при наведении кратко пояснять, что «Сначала нажмите «Редактировать»» или «Доступно в режиме редактирования», где это уместно.

9. **Диалог при открытии заказа контрагентом**  
   По ТЗ: если контрагент изменил заказ, при открытии показывать «Контрагент изменил данные заказа. Обновить данные?» и не снимать вопрос, пока данные снова не станут синхронизированы. Проверить наличие этого диалога и логики.

10. **Другие документы**  
    Для вкладки «Другие документы» либо реализовать минимальный функционал по ТЗ, либо явно показать заглушку «Раздел в разработке» вместо пустого экрана.
