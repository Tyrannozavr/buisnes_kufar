# Решение заказчика: «План Б» (соответствие ТЗ и дальнейшая полировка)

**Статус:** зафиксировано по переписке с Евгением. Файл предназначен для команды; выкладка в удалённый репозиторий по согласованию (локально может храниться без коммита).

**Дата фиксации:** 2026-04-05

## Контекст вопросов (кратко)

1. **«Создать счёт» и договоры с покупателем vs товар с автозаполненным заказом** — неоднозначность относительно основания (заказ как основание).
2. **«Заполнить данными»** — в ТЗ часто указано заполнение номера заказа и данных; откуда брать контекст при открытии редактора не из вкладки товаров (варианты: ограничить вход в редактор, оставить как есть).
3. **Радиокнопки реквизитов покупателя/поставщика** — в шаблон уже подставляются данные агентов; нужно ли упрощать.
4. **«Фото и сканы документов» в редакторе** — частично покрыто вкладкой «Документы»; дублировать в редактор или иная логика.

## Решение заказчика

- Принимается **«План Б»**: **выкатывать текущую реализацию как есть**, без доведения до идеала по формулировкам ТЗ на этом этапе.
- Обоснование:
  - Уже ожидается **новое ТЗ**, которое будет менять сайт.
  - Дальнейшее наращивание функционала **снова изменит структуру и логику** — нет смысла полировать сейчас, чтобы потом переделывать.
- Исключение: исправлять **прямо очевидные** проблемы, **от которых зависит тестирование**.
- После того как команда примет решение **«больше не нагружаем сайт функционалом»**, планируется **отладка и полировка** существующего: бэкенд — Дмитрий, фронтенд — Сергей (отдельная оплата).

## Следствия для разработки

- Не блокировать релизы спорными трактовками старых пунктов ТЗ, если они не ломают тесты и критический путь.
- Зафиксированные выше вопросы можно закрыть постфактум при стабилизации продукта и обновлённом ТЗ.

## Технические заметки (деплой 2026-04-05, без коммита в git)

- На продакшн-сервере репозиторий переключён на ветку **`preprod`** (`git reset --hard origin/preprod`), затем `docker compose up -d --build`. Автодеплой из CI по **`master`** при следующем пуше в `master` снова выставит код с `origin/master`, если не согласовать иначе.
- Скрипт **`scripts/run_migrations.sh`** на сервере вызывает сервис **`migrations`** со старым образом без полного набора ревизий Alembic; при ошибке «Can't locate revision» миграции на проде прогонялись командой:  
  `docker compose run --rm --no-deps backend poetry run alembic upgrade head` (актуальный код в контейнере **backend**).
- После выкладки **`preprod`** в логах фронта был **500** на `/api/_nuxt_icon/heroicons.json`: пакет **`@iconify-json/heroicons`** был в **devDependencies**, а образ собирается с `npm ci --omit=dev`. Исправление: перенести пакет в **`dependencies`** в `frontend/package.json` и обновить lockfile — правка внесена в рабочую копии и скопирована на сервер для пересборки **frontend**.
