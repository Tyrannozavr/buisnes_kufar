#### Что сделано (по ТЗ §A.2)

**Фронт — `frontend/pages/checkout.vue`**

- Группировка корзины по **`{продавец} + {Товары|Услуги}`** (ключ `companyId-orderType`).
- Заголовки по ТЗ: «Заказ на поставку **товаров**…» / «Заказ на оказание **услуг**…».
- Кнопка **«Подтвердить»** на каждый блок (раньше было «Отправить заказ» без разделения типов).
- Подтверждение **по одной группе** — товар и услуга одного продавца дают **два** заказа.
- После успеха — toast с переходом в **Закупки**; позиции группы убираются из корзины.
- Состояние загрузки `submittingGroupKey`, чтобы не дублировать отправку.

**API — `POST /api/v1/purchases/checkout`**

- Ответ **`CheckoutResponse`**: `{ deals: DealResponse[] }` (не один deal).
- **`create_deals_from_checkout`**: группировка по `(seller_id, OrderType)` — товары и услуги **разные** сделки.
- Тип заказа: `productType` из корзины или тип позиции в каталоге.
- Продавец: `companyId` в теле **или** определение по **slug** товара в каталоге (без `companyId` в payload).
- В `DealResponse` добавлено поле **`deal_type`** (`Товары` / `Услуги`).

**Чат — `backend/app/api/purchases/services/checkout_chat_notify.py`**

- После создания заказа — сообщение продавцу: номер заказа, тип (товары/услуги), список позиций.
- Ссылка **«Просмотр заказа»** → `/profile/editor?dealId=…&role=seller#order`.
- Чат создаётся/находится между компаниями автоматически.

**Дополнительно (не было явно в §2.2, но по переписке / для приёмки)**

- Тесты: `backend/tests/test_checkout_api.py` — split товар/услуга, один тип, уведомление в чат, seller по slug.
- Seed для ручной проверки: `backend/scripts/ensure_schet_test_users.py` — товар `test-checkout-bolt-m8` и услуга `test-checkout-montazh`.
- Инструкция проверки: [test-users.md](test-users.md) §2.2.
- `frontend/api/purchases.ts` — в checkout уходит `productType`; `companyId` продавца на бэкенде, не из buyer в теле.

#### Что сделано

**`GoodsColumns.vue`**

- Фильтр **только товарные** сделки на закладке «Товары».
- Все **9 колонок** по ТЗ; «Сопроводительные документы» (было «Закрывающие»).
- Колонка **«Счет-фактура»** → `#invoice` (бланк — заглушка, навигация работает).
- Формат ссылок: `formatDocumentLinkLabel` — `00012 от 08.04.2025 г.`
- **Сортировка** через `v-model:sorting` на `UTable` (Заказ, Дата, контрагент).
- Исправлены hash: `#accompanyingDocuments`, `#othersDocument` (было `#closingDocuments`).
- **«Создать счет»**: `createBill` с `fillFromDeal: true` — данные заказа подставляются сразу (как «СЧЕТ на основании»).
- **Пагинация**: 10 строк на страницу, без внутреннего скролла таблицы; блок пагинации — если строк > 10.
- **Ссылки**: `cursor-pointer` на всех кликабельных ячейках (заказ, документы).
- **Оптимизация загрузки**: batch `get_orders_by_ids`, `selectinload` компаний в `get_order_by_id`.

**`purchases.vue` / `sales.vue`**

- Вкладки **Товары | Услуги** (услуги — placeholder этап 4).
- `useDeals({ role: 'buyer' | 'seller' })` — загрузка только своей стороны.

**`EditorMenu` + бэкенд — read-only покупатель**

- `role=buyer`: скрыты «Редактировать», «Заполнить данными», «Сохранить», «Очистить», «Удалить», меню договора поставки.
- Остаются: Поиск, Печать, DOC, PDF; «Принять/Отклонить» при `confirmation=true`.
- API: `OnlySellerCanModifyDealError` → 403 на `PUT`, `POST /versions`, `DELETE`, `POST /bill|contract|supply-contract`, upload/delete документов.
- Исключение: `DELETE /versions` — покупатель может **отклонить** версию контрагента.

**`editor/index.vue`**

- Покупатель (`role=buyer`) — **read-only** на всех вкладках; поставщик редактирует.
- Вкладки «Сопроводительные» и «Счет-фактура» доступны для перехода из таблицы (бланк/заглушка — без toast).
