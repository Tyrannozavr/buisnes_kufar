## Scope

### 3.1. Диалог «Создать счет» (§D) ✅

| Задача | Детали | Статус |
|--------|--------|--------|
| Нет договоров | «С данным контрагентом нет договоров. Создать без основания?» Да/Нет | ✅ |
| Есть договоры | Список из ЛК «Договоры» + «Без договора» | ✅ |
| Результат | Переход на «Счет»; маска **00000** + дата | ✅ |
| Основание | Галка + текст `НОМЕР от ДАТА` на бланке и в меню | ✅ |
| Таблица «Продажи» | Номер договора в колонке «Договор» при привязке | ✅ |

#### Что сделано

**API — `GET /api/v1/purchases/company-contracts`**

- Таблица `company_contract` (договоры ЛК «Договоры» между компаниями).
- Список по `counterparty_company_id` для диалога «Создать счет».

**Фронт — `GoodsColumns.vue` + `useCreateBillFromSales.ts`**

- Клик «Создать счет» → проверка договоров с покупателем.
- Нет договоров → модалка Да/Нет.
- Есть договоры → выбор из списка + «Без договора».
- При выборе договора: `bill.reason`, галка «Основание», колонка «Договор» в Продажах.
- Счёт создаётся с номером/датой (`fillFromDeal: false`); полное заполнение — «Заполнить данными».

**Тесты:** `backend/tests/test_company_contracts_api.py`  
**Seed:** `ensure_schet_test_users.py` — 2 договора с основным покупателем, сделка 3 без договоров.

### 3.3. Заказ — синхронизация и расширение (§B.2) ✅

| Задача | Детали | Код | Ручная приёмка |
|--------|--------|-----|----------------|
| Два документооборота | Разные номера заказа у сторон; одинаковое содержимое в сделке | ✅ | — |
| Без автосинка | Изменение одной стороны не меняет заказ другой | ✅ | — |
| Уведомление | При сохранении → «Контрагент изменил данные заказа» (чат) | ✅ | ✅ (A) |
| Диалог | «Обновить данные?» при открытии до выравнивания | ✅ | ✅ (B) |
| «Создать ДОКУМЕНТ на основании» | Переход на вкладку + автозаполнение из заказа | ✅ | ✅ (D) |
| «Добавить продукт» | Выбор из прайса раздела «Продукция» ЛК | ✅ | ✅ (C) |
| Редактирование покупателем | Только вкладка «Заказ» | ✅ | ✅ (C) |
| Реквизиты на заказе | Read-only у обеих сторон; правки — ЛК «Данные компании» | ✅ | ✅ |
| SSR редактора | Форма не рендерится до загрузки сделки | ✅ | ✅ |

#### Что сделано (код)

- Backend: `POST/PUT .../deals` — фильтр полей заказа для **обеих** сторон; документы (`bill`, `contract`…) — только продавец и только при явном сохранении вкладки документа; `seller_company` — только `vat_rate` (`extra=forbid` на лишние поля)
- `createBodyForOrderUpdate` — тело версии с вкладки «Заказ» без документов (покупатель и продавец)
- `Order.vue` — реквизиты и подписи **всегда** read-only; редактируются: таблица товаров, комментарий, «Добавить продукт»
- `editor/index.vue` — `await ensureDealLoaded(dealId)` (SSR): спиннер вместо пустого бланка
- `editor/index.vue` — покупатель может войти в режим «Редактировать» только на вкладке «Заказ»
- `EditorMenu`: модалка «Обновить данные?»; `OrderProductPicker`; `OrderMenu` — «СЧЕТ / ДОГОВОР ПОСТАВКИ на основании» (только продавец, вкладка «Заказ»)
- Тесты: `test_deal_change_review_api.py` (buyer/seller order version, запрет bill/requisites)
