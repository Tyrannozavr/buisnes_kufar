## A. Дополнения к основной части сайта

### A.1. Единицы измерения (ОКЕИ) → **этап 2**

- Код ОКЕИ у каждой единицы в справочнике.
- Автоподстановка кода в таблицах **заказа** и **счёта** по выбранной единице.

### A.2. Страница подтверждения → **этап 2** ✅

- Корзина → «Оформить заказ» → страница подтверждения.
- Заказы по продавцам (товары / услуги — отдельные заказы).
- «Подтвердить» → «Закупки» покупателя + «Продажи» продавца.
- Уведомление продавцу в чате (со ссылкой на заказ в редакторе).

→ Детали реализации: [etap-02](etap-02-schet-na-oplatu.md) §2.2

### A.3. Закладка «Товары» (ЛК) → **этап 2**

Таблицы продавца и покупателя: Заказ, Дата, контрагент, Состояние, Счет, Договор поставки, Сопроводительные документы, Счет-фактура, Другие документы.

- Маски **00000**, дата в названии, ежегодное обнуление.
- Сортировки: Заказ, Дата, контрагент (А–Я).
- «Создать счет» / «Просмотр» → редактор на нужной вкладке.
- У покупателя «Просмотр» — read-only, в т.ч. фото/сканы счёта.

*(Колонка «Договор» при выборе договора в диалоге — **этап 3**.)*

### A.4. Закладка «Услуги» (ЛК) → **этап 4**

Таблицы: Заказ, Дата, контрагент, Состояние, Счет, Договор, Акт, Счет-фактура, Другие документы.

- Та же логика масок, ссылок и «Просмотр» / «Создать …», что для товаров.
- Ссылки на вкладки: «Договор услуг/работ», «Акт оказания услуг».

## B. Редактор документов — закладка «Заказ»

### B.1. Форма и команды → **этап 2**

- A4, до 10 страниц; статические / редактируемые / read-only поля.
- Номер заказа **00000**, дата создания.
- Таблица товаров из корзины; сумма = кол × цена; итоги и пропись.
- **Должностные лица** на форме заказа (из ЛК).
- **Заполнить данными** — только номер и дата, затем заполнение; модалка «Данные будут изменены…»; сохранённые данные = новые «заводские».
- **Предварительный просмотр**, **Печать**, **DOC**, **PDF**.
- **Удалить данные** (кроме номера и даты).
- **Сохранить документ**.

*(Семантика «Заполнить данными» для текущей сделки — **этап 1**.)*

### B.2. Синхронизация и расширение заказа → **этап 3**

- Два независимых документооборота (покупатель / поставщик); номера заказов разные, содержимое идентично в рамках сделки.
- Изменение одной стороны **не** меняет заказ другой автоматически.
- При сохранении — сообщение контрагенту: «Контрагент изменил данные заказа».
- При открытии — диалог «Обновить данные?» до выравнивания версий.
- **«Создать ДОКУМЕНТ на основании»** — переход на вкладку + автозаполнение.
- **«Добавить продукт»** — выбор наименования/артикула из прайса раздела «Продукция» ЛК.

### B.3. Фото/Сканы на «Заказ» → **этап 2**

- Блок «Фото/Сканы документа»: файл, превью, Удалить, Сохранить локально.
- **Отправить контрагенту** → чат + блок сканов у заявки.
- Покупатель — просмотр без редактирования. Референс UX: Elba (ссылка в `.docx`).

## C. Редактор — закладка «Счет» (общее)

→ **этапы 2–4** (по типу документа)

- A4, книжная ориентация.
- Выпадающий список **«Тип документа»**: счёт на оплату / счёт-договор / счёт-оферта (по умолчанию — на оплату).
- Общие команды: Заполнить данными, предпросмотр, печать, DOC, PDF, **Удалить данные**, Сохранить.
- Формат чисел: `1,200.00`; пропись с копейками.

## D. §3 «Создать счет» (из таблицы «Продажи») → **этап 3**

- Нет договоров → «Создать без основания?» Да/Нет.
- Есть договоры → список из ЛК «Договоры» + «Без договора».
- При выборе договора: галка «Основание», текст `НОМЕР от ДАТА`, номер в колонке «Договор» заявки.
- Новый счёт: маска **00000** + текущая дата.
- API договоров (при необходимости — merge `features/document-layer`).

## E. Счет на оплату → **этап 1** (база) + **этап 2** (полное §5)

- Верхняя таблица реквизитов — **seller** (этап 1).
- Заголовок, черта, поставщик/покупатель с индексом, основание по галке.
- Таблица товаров, итого, НДС, всего к оплате, пропись.
- Срок оплаты, доп. информация (вкл. по умолчанию), подписи 1–3.
- Галки: основание, НДС (дефолт из ЛК), срок оплаты, доп. информация.
- DOC/PDF/печать/просмотр = экран.
- Фото/Сканы — **этап 2**.
