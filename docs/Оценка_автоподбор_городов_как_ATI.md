# Оценка: автоподбор городов по вводу текста (как на ATI)

## Что хочет заказчик

По вводу текста в поле «Откуда» / «Куда» (или аналог) показывать выпадающий список вариантов из **нашей базы городов России**, в формате как на trucks.ati.su:

- Одно поле ввода, при вводе (например, «минск») под полем появляется выпадающий список.
- Каждый вариант — строка вида: **«Город, Регион, Страна»** (например: «Минск, Минская область, Беларусь»).
- Список прокручивается, если вариантов много.
- Выбор пункта подставляет полную подпись в поле и сохраняет выбранный город.

## Как это сделано у нас сейчас

- **База**: своя БД городов России (таблицы `cities`, `regions`, `federal_districts`, `countries`) — уже есть и наполнена (в т.ч. из `data_cities/complete_cities_db_final.sql`).
- **API**: `GET /api/v1/locations/cities?country_code=RU&search=<текст>` — поиск по подстроке названия города (`ILIKE %текст%`), без региона. Ответ: `{ items: [{ label, value }], total }`. Сейчас в `label` и `value` отдаётся только **название города**, без региона и страны.
- **Фронт**: в форме компании уже есть поиск города с задержкой (debounce) и вызов этого API, но с каскадом «страна → регион → город» и подсказки только по названию города.

## Что нужно доработать

### 1. Бэкенд (низкая сложность)

- В эндпоинте списка городов (например, в `location_tree.get_cities`) при наличии параметра `search` и отсутствии привязки к региону:
  - в `label` отдавать строку формата **«Город, Регион, Страна»** (подтянув регион и страну по связям);
  - в `value` оставить название города или id (как договоритесь для сохранения в заявках/фильтрах);
  - ограничить выборку лимитом (например, 20–30 записей) и сортировкой (например, по населению или по релевантности), чтобы при запросе «а» не отдавать сотни городов.

Альтернатива: отдельный эндпоинт типа `GET /api/v1/locations/cities/autocomplete?q=минск&country_code=RU` с таким же форматом ответа — тогда текущий `get_cities` не трогаем.

Оценка: **1–2 часа**.

### 2. Фронтенд (средняя сложность)

- Вынести автоподбор в переиспользуемый компонент (например, `CityAutocomplete`):
  - поле ввода;
  - при вводе (с debounce 200–300 мс) запрос к API городов с `search=<текст>`;
  - под полем выпадающий список с вариантами `label` («Город, Регион, Страна»);
  - при выборе пункта — подставить выбранный текст в поле и отдать наружу выбранный город (id/название) через `v-model` или emit.
- Подключить этот компонент туда, где нужен выбор города из базы (форма компании, фильтры поиска и т.д.), заменив или дополнив текущий выбор города.

Оценка: **2–4 часа** (компонент + интеграция в 1–2 экрана).

### 3. Опционально

- Показывать в подсказках не только города, но и регионы (как на ATI: «Минская область, Беларусь») — потребуется расширить поиск на таблицу регионов и объединить результаты, плюс разметка в UI (отдельный тип строки или разделитель). Оценка: **+1–2 часа**.

## Итоговая оценка сложности и стоимости

| Задача                         | Сложность   | Время   |
|--------------------------------|-------------|---------|
| Бэкенд: формат «Город, Регион, Страна» + лимит | Низкая      | 1–2 ч   |
| Фронт: компонент автоподбора + интеграция      | Средняя     | 2–4 ч   |
| Опционально: регионы в подсказках             | Средняя     | +1–2 ч  |

**Без учёта регионов в подсказках**: порядка **3–6 часов** чистой разработки.  
**С регионами в подсказках**: порядка **4–8 часов**.

Сторонние API и платные сервисы не требуются — всё по своей БД городов России.

## Рекомендация

Реалистичный и быстрый вариант — сделать в первую очередь:

1. На бэкенде при `search` без региона возвращать в `label` строку «Город, Регион, Страна» и ограничить выборку (limit 20–30).
2. На фронте один компонент автоподбора с выпадающим списком и debounce, подключить его в форму компании (и при необходимости в фильтры).

После этого можно отписать заказчику варианты и стоимость (в часах или в рублях по вашей ставке).
